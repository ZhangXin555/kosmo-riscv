# 五级流水详解：这一颗 CPU 是怎么跑起来的

> 这份文档回答三个问题：
> 1. 五级流水到底在"流"什么？
> 2. 一条指令经过五级，每一拍发生了什么？
> 3. 分支、load-use、旁路这三件事，为什么必须这么处理？

---

## 一、先理解"流水"这两个字

### 1.1 不流水会怎样

假设没有流水，一条指令要依次做五件事：取指 → 译码 → 执行 → 访存 → 写回。
每一件事都要占一个时钟周期，那么一条指令 = 5 拍，10 条指令 = 50 拍。

问题在于：**同一时刻只有一小部分电路在工作**。取指的时候 ALU 在闲着，算的时候 ROM 在闲着。

### 1.2 流水做的就是"叠起来"

把五件事拆成五个工位，指令像流水线上的零件一样，一个工位做完交给下一个工位，自己立刻接新活。

| 拍 | 工位 1 (IF) | 工位 2 (ID) | 工位 3 (EX) | 工位 4 (MEM) | 工位 5 (WB) |
|---|---|---|---|---|---|
| 1 | 指令1 | | | | |
| 2 | 指令2 | 指令1 | | | |
| 3 | 指令3 | 指令2 | 指令1 | | |
| 4 | 指令4 | 指令3 | 指令2 | 指令1 | |
| 5 | 指令5 | 指令4 | 指令3 | 指令2 | 指令1 |
| 6 | 指令6 | 指令5 | 指令4 | 指令3 | 指令2 |

从第 5 拍开始，**每一拍都有一条指令完成**。理想情况下 CPI（每指令周期数）= 1。

我们的 CPU 实测 CPI = 1.07，多出来的 0.07 全是"流水线被打断"的代价（分支冲刷 + load-use 停顿）。

## 二、五个工位各自干什么

### IF（Instruction Fetch，取指）—— `cpu_IFU.sv`

**做的事**：把 PC 送到指令 ROM，把 ROM 返回的 32 位指令拿进来；同时算出下一条 PC。

```systemverilog
assign snpc = pc + 32'd4;    // 顺序执行就是 +4
assign inst = irom_data;     // ROM 是组合读，当拍就出
```

PC 怎么更新，有四种情况，优先级从上到下：

```systemverilog
if (reset)                             pc <= 32'h8000_0000;  // ① 复位
else if (stall && valid && ready)      pc <= pc;             // ② 停顿（load-use）
else if (dnpc_flag && valid && ready)  pc <= dnpc;           // ③ 跳转/分支
else                                   pc <= snpc;           // ④ 正常 +4
```

**关键概念 `dnpc`**：下一条指令地址。正常是 `pc+4`，跳转时由后续级算出来送回来。

---

### ID（Instruction Decode，译码）—— `cpu_IDU.sv`

**做的事**（这是最忙的一级）：

1. 从 32 位指令里拆出 `opcode`(7位) / `rd`(5位) / `funct3`(3位) / `rs1`(5位) / `rs2`(5位)
2. 按 opcode 生成所有控制信号：要不要写寄存器、要不要访存、是不是分支……
3. 算出立即数（RISC-V 有 **6 种**立即数格式，位序各不相同，这是最容易写错的地方）
4. 从寄存器堆读 `rs1` / `rs2`（组合读，不占周期）
5. 算出分支目标 `branch_pc = pc + imm`

**为什么 ID 这么复杂**：RISC-V 是定长 32 位指令，但不同指令类型的立即数被拆散在指令的不同位置。比如 B 型（分支）的立即数是这样拼的：

```
imm[12|10:5] 在 inst[31:25]
imm[4:1|11]  在 inst[11:7]
```

必须按位重新拼起来，还要补符号位、左移 1 位（因为指令地址 2 字节对齐，最低位永远是 0）。

---

### EX（Execute，执行）—— `cpu_EXU.sv` + `cpu_ALU.sv`

**做的事**：

1. ALU 算出运算结果（11 种运算）
2. 判断分支是否成立（结果 bit0）
3. 算出跳转目标（`rs1 + imm`，或者 `pc + imm`）

**一个巧妙的小技巧**：

```systemverilog
assign Ex_result = alu_result ^ {31'd0, inv_flag_reg};
```

`beq` 需要"相等"，但 ALU 里只算了"不相等"（`equal = (d1 != d2)`）。与其再加一个比较器，不如在 EX 级把结果 bit0 翻一下 —— 一条 XOR 就够了。

---

### MEM（Memory，访存）—— `cpu_LSU.sv`

**做的事**：

1. 把地址、写数据、写使能、字节掩码送到总线
2. 从总线读回来的数据按 `funct3` 做符号扩展或零扩展

**字节/半字/字怎么区分**：

```systemverilog
assign mask = funct3_reg[1:0];   // 00=1字节 01=2字节 10=4字节
```

读回来之后：

```systemverilog
case (funct3_reg)
    3'b000: rdata_ex = rdata_8i;    // lb  ：取低 8 位，符号扩展
    3'b001: rdata_ex = rdata_16i;   // lh  ：取低 16 位，符号扩展
    3'b010: rdata_ex = rdata;       // lw  ：整字
    3'b100: rdata_ex = rdata_8u;    // lbu ：取低 8 位，零扩展
    3'b101: rdata_ex = rdata_16u;   // lhu ：取低 16 位，零扩展
endcase
```

---

### WB（Write Back，写回）—— `cpu_WBU.sv`

**做的事**：从三个候选值里选一个，写回寄存器堆。

```systemverilog
assign rd_value_next = (jump_flag | (|csr_wen)) ? rd_value   // ① 跳转/CSR
                     : (mem_ren)                ? MEM_Rdata  // ② load
                     :                             Ex_result; // ③ ALU
```

**注意 WB 是纯组合的**，没有寄存器。所以物理上只有 **4 个触发器级 + 1 个组合级 = 5 级流水**。

**防幽灵写回**：

```systemverilog
assign R_wen_next = R_wen & valid;   // 被冲刷掉的指令不许写寄存器
```

## 三、一条指令的五拍（逐拍表）

以 `add x3, x3, x2` 为例（假设它前面和后面都有指令）：

| 拍 | IF 在做什么 | ID 在做什么 | EX 在做什么 | MEM | WB |
|---|---|---|---|---|---|
| N | 取 add | 译码上一条 | 执行上上条 | 访存上上上条 | 写回上上上上条 |
| N+1 | 取 add 的下一条 | **译码 add，读 x3/x2** | … | … | … |
| N+2 | … | 译码下一条 | **ALU 算出 x3+x2** | … | … |
| N+3 | … | … | … | **结果往下传** | … |
| N+4 | … | … | … | … | **写回 x3** |

所以一条指令从进 IF 到写回完成要 5 拍，但**吞吐是每拍一条**。

## 四、三个必须处理的麻烦

### 4.1 数据冒险 & 旁路（forwarding）

**问题**：

```asm
addi x1, x0, 5     # 第 1 条：x1 = 5
add  x2, x1, x1    # 第 2 条：马上要用 x1
```

第 2 条在 ID 级读寄存器堆时，第 1 条还在 EX 级 —— **它的结果还没写回**。读到的 x1 是旧值。

**解法**：不读寄存器堆了，直接从 EX 级的输出线上把结果"拉"过来。这就是旁路。

我们的实现分两步：

1. `cpu_Data_hazard.sv` 判断"EX 要用的寄存器是不是刚被写过"，输出一个 4 档码
2. `cpu_Control.sv` 用这个码做四选一

| 码 | 数据从哪来 | 什么时候用 |
|---|---|---|
| `2'b00` | 寄存器堆读出的原值 | 没人写这个寄存器 |
| `2'b01` | EX 级的 `Ex_result` | 前一条指令刚在 EX 算完 |
| `2'b10` | MEM 级的 `Ex_result` | 前两条指令在 MEM |
| `2'b11` | MEM 级 load 回来的数据 | 前一条是 load（数据在 MEM 末尾才出来） |

**为什么 EX 优先于 MEM**：EX 的结果更新，如果两条指令写同一个 rd，必须用新的那条。

---

### 4.2 load-use 停顿

**问题**：

```asm
lw  x1, 0(x2)      # 第 1 条：x1 要从内存读
add x3, x1, x1     # 第 2 条：马上要用 x1
```

`lw` 的数据要到 **MEM 级末尾**才出来。第 2 条在 EX 级就要用，旁路也来不及 —— 只能**停一拍**。

**判断条件**（只有一行，但很关键）：

```systemverilog
assign stall_condition = EXU_mem_ren && (rs1_hazard || rs2_hazard);
assign IFU_stall       = stall_condition;
```

- `EXU_mem_ren`：EX 这条是 load
- `rs1_hazard`/`rs2_hazard`：ID 这条要用的寄存器，正好是 load 的目标

`stall` 拉高后：

- IF 的 PC 保持不变（不取新指令）
- ID/EX 寄存器保持（不往下传）
- EX/MEM 寄存器**插入一个气泡**（`valid` 清 0）

这样停一拍之后，load 的数据正好在 MEM 末尾出来，下一条在 EX 就能通过 `2'b11` 旁路拿到。

---

### 4.3 分支冲刷

**问题**：

```asm
beq x1, x2, target   # 分支
add x3, x4, x5       # 这条可能不该执行
sub x6, x7, x8       # 这条也可能不该执行
```

分支在第 1 条进 EX 时才知道成不成立，但此时第 2、3 条**已经被取进来了**。如果分支成立，这两条必须作废。

**解法**：`dnpc_flag` 拉高 → IF 直接跳到 `dnpc`，同时把两级流水寄存器的 `valid` 清 0（气泡）。

代价是 **2 拍**（我们做过逐拍 trace 验证：分支成立后，EX 和 MEM 各有一个气泡）。

**怎么减少这个代价**：加分支预测。我们另做了一个版本（P4），在 IF 级就猜"分支跳不跳"，命中率约 50% 时省下 12.4% 的周期数（1605 → 1406 拍）。

## 五、真实的逐拍 trace

我们用 `C:\temp\trace` 里的测试平台打印了每拍各级的状态。关键几拍：

| 周期 | IF | ID | EX | MEM | WB | 说明 |
|---|---|---|---|---|---|---|
| 0 | pc=0x80000000 | — | — | — | — | 复位释放，只有 IF 有活 |
| 1 | pc=0x80000004 | 第1条 | — | — | — | 流水线开始灌水 |
| 2 | pc=0x80000008 | 第2条 | 第1条 | — | — | |
| 3 | … | 第3条 | 第2条 | 第1条 | — | |
| 4 | … | 第4条 | 第3条 | 第2条 | 第1条 | 填满，之后每拍一条 |
| 9 | | **bne 在 ID** | | | | 分支指令译码 |
| 10 | | | **bne 在 EX，算出成立** | | | `Ex_result[0]=1` → 跳转 |
| 11 | **pc 跳到目标** | 气泡 | | | | `dnpc_flag` 生效 |
| 12 | | | | 气泡 | | 冲刷的第 2 条也作废 |

从表里能清楚看到：**分支成立后，EX 和 MEM 各插入一个气泡 = 2 拍惩罚**。

## 六、如果想自己复刻，按这个顺序写

1. **先写单周期的**：`IFU → IDU → EXU → LSU → WBU` 串起来，不插流水寄存器。跑通再看流水。
2. 加 `cpu_Reg.sv`，把 `IFID_EX_Reg` 和 `EX_LSWB_Reg` 插进去，变成五级。这时候**不做旁路**，会算错，但能跑。
3. 加 `cpu_Data_hazard.sv` + `cpu_Control.sv` 的旁路部分，数据对了。
4. 加 `stall_condition`，解决 load-use。
5. 加 `dnpc_flag` + `valid` 清除，解决分支冲刷。
6. 最后加 `cpu_CSR.sv` 和异常通路（可选）。

**每加一步都要跑测试程序**。我们的测试程序是 `sim/prog.s`，跑完会把结果写到 `0x8010_00F0`，测试平台捕获后打印：

```
RESULT_CYCLES=1604 DONEVAL=00004e84
TOTAL_CYCLES=1605 DRAM0=00004e84
```

- `DONEVAL` 是程序算出来的结果，必须跟手算一致（0x4e84 = 20100）
- `TOTAL_CYCLES` 是总周期数，用来算 CPI

## 七、常见误解

| 误解 | 事实 |
|---|---|
| "五级流水就是五个 always 块" | 不是。每一级是一个**组合逻辑块 + 一个流水寄存器**，寄存器才是"级"的分界 |
| "CPI 一定是 1" | 只有理想情况。分支和 load-use 一定会拉高 CPI |
| "旁路可以解决所有冒险" | 解决不了 load-use，因为数据物理上还没出来 |
| "WB 级也要一个寄存器" | 不需要。WB 是纯组合的选通，选完直接写寄存器堆 |
| "分支越早判定越好" | 越早越省周期，但组合路径越长、频率上不去。我们在 EX 级判定，是频率和 CPI 的折中 |
