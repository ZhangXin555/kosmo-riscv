## 一、准备工作

### 你需要的软件

| 软件 | 用途 | 版本 | 是否必须 |
|---|---|---|---|
| Vivado | 仿真、看代码、综合、看结构 | 2020.1 及以上（我们用 2025.2 验证） | **必须**（跑仿真就要） |
| Pango Design Suite | 出紫光位流、烧板 | 2025.2 | 只有要上板才需要 |
| 文本编辑器 | 看代码 | VSCode / Notepad++ | 建议 |

### 检查 Vivado 装在哪

打开 PowerShell，输入：

```powershell
Get-Command xvlog.bat -ErrorAction SilentlyContinue
```

如果什么都没输出，说明 Vivado 的 `bin` 目录不在 PATH 里。常见安装位置：

```
D:\vivado\2025.2\Vivado\bin
C:\Xilinx\Vivado\2023.2\bin
```

记住这个路径，下面第 2 步要用。

## 二、跑仿真（最快看到结果）

### 方式 A：双击 bat（Windows）

1. 打开 `sim` 目录
2. 双击 `run_xsim.bat`
3. 弹出一个黑窗口，几十秒后出现：

```
RESULT_CYCLES=1604 DONEVAL=00004e84
TOTAL_CYCLES=1605 DRAM0=00004e84
```

**成功标志**：`DONEVAL=00004e84`（= 20100，测试程序算出来的正确结果）。

### 方式 B：手动三步（跨平台 / 想看细节）

```bash
cd sim

# 1) 编译（注意：xvlog 不认 -timescale 参数，所以源文件里已经写好 `timescale）
xvlog -sv ../rtl/*.sv ../rtl/*.v tb.sv

# 2) 链接
xelab tb -s tb

# 3) 运行
xsim tb -R
```

在 PowerShell 里跑 `xvlog -sv ../rtl/*.sv` 会报 `Can not find file: *.sv` —— 因为 PowerShell 不会帮你展开通配符。换成：

```powershell
$files = @(Get-ChildItem ../rtl/*.sv, ../rtl/*.v | ForEach-Object { $_.FullName })
xvlog -sv @files tb.sv
```

### 看不懂输出？

| 输出 | 含义 |
|---|---|
| `RESULT_CYCLES=1604` | 程序跑完用了 1604 个周期（不含复位那 5 拍） |
| `DONEVAL=00004e84` | 程序把 20100 写到了 `0x8010_00F0`，测试平台捕获到了 |
| `TOTAL_CYCLES=1605` | 总周期数（含最后那次写） |
| `DRAM0=00004e84` | 数据存储器第 0 个字的最终值 |
| `TIMEOUT_CYCLES=...` | **出错了**：程序没跑完。看是不是指令写错/死循环 |

### 想改路径

`run_xsim.bat` 第 10 行左右：

```bat
set VIVADO_BIN=D:\vivado\2025.2\Vivado\bin
```

改成你自己的 Vivado 路径。

## 三、建 Vivado 工程

### 方式 A：Tcl 脚本（推荐）

打开 Vivado → 底部 `Tcl Console`：

```tcl
cd D:/path/to/kosmo-riscv
source scripts/create_project.tcl
```

最后会打印：

```
DONE. 工程已生成: D:/path/to/kosmo-riscv/kosmo_riscv/kosmo_rtl.xpr
```

双击这个 `.xpr` 就能打开。

### 方式 B：命令行（不打开 GUI）

```bash
cd /path/to/kosmo-riscv
vivado -mode batch -source scripts/create_project.tcl -nolog -nojournal
```

### 方式 C：手动新建（理解每一步在干什么）

1. Vivado → `Create Project` → 名字随便 → 位置选仓库根目录
2. **Project Type** 选 `RTL project`，勾上 `Do not specify sources at this time`
3. **Default Part** 随便选一个（比如 `xc7a100tcsg324-1`）—— 反正 Vivado 没有紫光器件
4. 建好后：`Add Sources` → `Add or create design sources` → `Add Files` → 把 `rtl/` 下 27 个文件全选进来
5. `Add Sources` → `Add or create constraints` → 加 `constrs/kosmo_pins.xdc`
6. `Add Sources` → `Add or create simulation sources` → 加 `sim/tb.sv`
7. 左侧 `PROJECT MANAGER` → 右键 `top` → `Set as Top`（如果没自动设置）
8. 仿真：右键 `tb` → `Set as Top`（sim_1 里）

## 四、跑综合，看资源和结构

### 4.1 跑综合

左侧 `SYNTHESIS` → `Run Synthesis` → 等 1~3 分钟。

**成功标志**：右上角绿色 `Synthesis Complete`，Messages 里 `0 Errors`。

### 4.2 看资源

综合完成后：`Open Synthesized Design` → 菜单 `Reports` → `Report Utilization`。

我们实测（含 64 KB 指令 ROM）：

| 资源 | 用量 |
|---|---|
| LUT | 3119 |
| FF（触发器） | 1687 |
| RAMB36 | 64（指令 ROM 用掉了） |
| DSP | 0 |

**5 级流水在哪看**：

- `IFID_EX_Reg_inst0`：476 LUT / **184 FF** ← ID/EX 流水寄存器
- `EX_LSWB_Reg_inst0`：427 LUT / **113 FF** ← EX/MEM 流水寄存器
- 两个加起来 297 个 FF = 五级流水的"级间存储"

### 4.3 看结构图

`Open Synthesized Design` → 左侧 `Schematic`（或者 RTL 阶段看 `RTL ANALYSIS → Schematic`）。

Netlist 面板里展开 `top → Core_cpu → ...`，能看到：

```
Core_cpu (myCPU)
├── EX_LSWB_Reg_inst0 (EX_LSWB_Reg)
├── EXU_Inst0 (EXU)
├── IDU_inst0 (IDU)
│   └── Reg_Stack_inst0
│       ├── CSR_inst0
│       └── Reg_inst0 (RegisterFile)
├── IFID_EX_Reg_inst0
└── IFU_inst0
```

> 注意：综合器可能把 `EXU`/`LSU`/`WBU` 这些纯组合模块 flatten 掉（合并进父模块），这是正常的优化，不代表逻辑丢了。判断结构在不在，看**流水寄存器的 FF 数**最可靠。

### 4.4 看时序（只是估算）

`Open Synthesized Design` → `Report Timing Summary`。

⚠️ **这个数字是 Artix-7 的**，不是紫光 PG2K100 的。只能参考，不能当板子的真实 Fmax。

## 五、出紫光位流（Pango Design Suite）

> 只有这一步能产出真正能烧到 Kosmo 板子上的文件。
> Vivado 里的器件是占位，出不了紫光位流。

### 5.1 建 PDS 工程

打开 Pango Design Suite → `New Project`：

| 项 | 值 |
|---|---|
| Project Name | `kosmo_riscv` |
| Project Location | 随便 |
| Project Type | `RTL project` |
| **Family** | **Kosmo2** |
| **Device** | **PG2K100** |
| **Package** | **MBG400** |
| **Speed Grade** | **-6** |
| Synthesis Tool | ADS |

然后 `Add Files` → 加 `rtl/` 下 27 个文件 → `Next` → `Part` 确认 → `Finish`。

### 5.2 约束文件转换

PDS 用的是 `.fdc` 格式，不是 `.xdc`。转换规则：

**XDC 里**：

```tcl
set_property -dict {PACKAGE_PIN T9   IOSTANDARD LVCMOS33} [get_ports {clk}]
set_property -dict {PACKAGE_PIN W13  IOSTANDARD LVCMOS33} [get_ports {rst_n}]
set_property -dict {PACKAGE_PIN G14  IOSTANDARD LVCMOS33} [get_ports {led[0]}]
...
create_clock -name clk -period 20.000 [get_ports {clk}]
```

**FDC 里**：

```
define_attribute {p:clk}   {PAP_IO_LOC} {T9}
define_attribute {p:clk}   {PAP_IO_VCCIO} {3.3}
define_attribute {p:clk}   {PAP_IO_STANDARD} {LVCMOS33}
define_attribute {p:clk}   {PAP_IO_DIRECTION} {INPUT}

define_attribute {p:rst_n} {PAP_IO_LOC} {W13}
define_attribute {p:rst_n} {PAP_IO_STANDARD} {LVCMOS33}
define_attribute {p:rst_n} {PAP_IO_DIRECTION} {INPUT}

define_attribute {p:led[0]} {PAP_IO_LOC} {G14}
define_attribute {p:led[0]} {PAP_IO_STANDARD} {LVCMOS33}
define_attribute {p:led[0]} {PAP_IO_DIRECTION} {OUTPUT}
...
create_clock -name {clk} [get_ports {clk}] -period {20.000} -waveform {0.000 10.000}
```

### 5.3 用图形界面配引脚（更直观）

`Tools` → `Open Design Workspace` → 底部 `I/O Table`：

- 在 `LOC` 列双击，填引脚号（如 `T9`）
- 在 `IOSTANDARD` 列填 `LVCMOS33`
- 填完 `File` → `Save Constraint File`，会自动生成 `.fdc`

### 5.4 跑流程

左侧 Flow 树，从上到下依次双击（或右键 `Rerun`）：

```
Synthesis
  ├── Compile            ← 编译
  └── Synthesize         ← 综合
Place and Route
  ├── Device Map         ← 器件映射（这里会检查引脚约束）
  ├── Place              ← 布局
  ├── Route              ← 布线
  ├── Route Optimize     ← 布线优化
  └── Report Timing      ← 看时序
Bitstream
  └── Generate Bitstream ← 出位流
```

产物：`prj_tasks/pnr_1/generate_bitstream/top.sbit`

### 5.5 看时序是否收敛

`Report Timing` 的 Report 里找：

```
Design Summary : All Constraints Met.
```

以及：

```
clk   50.0000 MHz   75.3409 MHz   20.0000   13.2730   Slack 6.727
```

- 第一列是约束频率
- 第二列是估算的 Fmax
- 最后一列 Slack：**正数 = 收敛**，负数 = 没收敛

我们三版实测：

| 约束 | 估算 Fmax | Slack | 结论 |
|---|---|---|---|
| 50 MHz | 75.34 MHz | +6.727 | ✅ |
| 100 MHz | 110.10 MHz | +0.917 | ✅ |
| 125 MHz | 130.84 MHz | +0.357 | ✅ |

## 六、烧到板子上

### 6.1 连 JTAG

板子 JTAG 口 → 下载器 → 电脑 USB。装好驱动后，PDS 能识别。

### 6.2 打开烧录工具

PDS 菜单 `Tools` → `Configuration`，打开 `Fabric Configuration` 窗口。

### 6.3 扫链

1. 左侧双击 `Boundary Scan`
2. 空白处右键 → `Scan Device`
3. 应该看到两个器件：`Arm-PU` 和 `Kosmo2-PG2K100`（**必须两个都出现**，只出现一个说明链不对）

### 6.4 指定位流

右键 `Kosmo2-PG2K100` → `Assign New Configuration File` → 选 `top.sbit`。

### 6.5 烧

右键那个器件 → `Program` → 等几秒。

**成功标志**：
- 控制台打印 `[时间] Finish program D:/.../top.sbit` 和 `The done bit is 1`
- 板上 `DONE` 灯亮（如果板子有这个灯）

### 6.6 常见烧录错误

| 错误 | 原因 | 解决 |
|---|---|---|
| `E: Configuration-0013: PU at location 0 has no bitstream file` | 链上有两个器件，PU 那个没指定位流 | 只给 PG2K100 指定，或者先把 PU 从链上删掉 |
| `E: JtagServer-0308: The count of devices added to the JTAG chain does not match the hardware` | 链上的器件数和实际不符 | 重新 `Scan Device`，不要手动添加 |
| `E: Configuration-0003: The bitstream file doesn't match the device` | 位流和选中的器件不匹配 | 确认选的是 PG2K100 不是 PU |

## 七、改程序（重新生成 prog.hex）

测试程序的流程是：写汇编（`prog.s`）→ 汇编器（`asm.py`）→ 机器码（`prog.hex`）→ 仿真读它。

### 7.1 看汇编

`sim/prog.s`：

```asm
lui   x1, 0x80100     # x1 = 0x80100000（数据存储器基址）
lui   x7, 0x80200     # x7 = 0x80200000（外设基址）
addi  x2, x0, 200     # 循环 200 次
addi  x3, x0, 0       # 累加器清零
loop:
add   x3, x3, x2
lw    x5, 0(x1)
sw    x3, 0(x1)
add   x6, x3, x5
or    x3, x6, x3
addi  x2, x2, -1
bne   x2, x0, loop
sw    x3, 240(x7)     # 把结果写到 0x802000F0 → 测试平台捕获
halt: jal x0, halt
```

### 7.2 改程序后重新汇编

```bash
cd sim
python asm.py prog.s > prog.hex
```

`asm.py` 是个很简陋的汇编器，只支持本程序用到的指令。如果你的新程序用了它不认识的指令，需要自己扩展它。

### 7.3 跑仿真验证

```bash
run_xsim.bat
```

看 `DONEVAL` 是不是你期望的结果。

## 八、常见报错怎么解决

### 8.1 仿真相关

| 报错 | 原因 | 解决 |
|---|---|---|
| `ERROR: [XSIM 43-4316] Can not find file: *.sv` | PowerShell 不展开通配符 | 用 `@files` 展开列表 |
| `ERROR: [XSIM 43-4099] Module xxx doesn't have a timescale but at least one module in design has a timescale` | 有的文件有 `` `timescale `` 有的没有 | 给所有文件都加上 `` `timescale 1ns/1ps `` |
| `$readmemh: File prog.hex not found` | 工作目录不对 | 必须在 `sim/` 目录下跑 |
| `TIMEOUT_CYCLES=2000000` | 程序死循环或指令错 | 检查汇编/机器码 |

### 8.2 Vivado 综合相关

| 报错 | 原因 | 解决 |
|---|---|---|
| `[Synth 8-524] part-select [39:0] out of range of prefix 'seg_wdata'` | 端口 40 位，内部变量 32 位 | 把内部变量也改成 40 位 |
| `[Synth 8-11365] named port connection 'xxx' does not exist` | 例化时连了模块没有的端口 | 对照模块定义删掉 |
| `[Common 17-55] 'set_property' expects at least one object` | xdc 里约束了不存在的端口 | 删掉那条约束 |
| `Loop limit 2000 exceeded`（PDS） | for 循环太多次 | 大数组初始化改成 `$readmemh`，或删掉 |

### 8.3 PDS 相关

| 报错 | 原因 | 解决 |
|---|---|---|
| `E: Verilog-4039 Identifier 'logic' is not declared` | `.sv` 文件被当成 Verilog-2001 编译 | 综合选项加 `-verilog_standard SystemVerilog` |
| `E: ConstraintEditor-0099: Port 'xxx' unspecified I/O constraint` | 有端口没约束 | 补约束，或从顶层删掉该端口 |
| `invalid command name "close_project"` | PDS 的 Tcl 没有这个命令 | 无害，忽略 |

## 九、一句话总结

| 你想做什么 | 走哪条路 |
|---|---|
| 看这个 CPU 对不对 | `cd sim && run_xsim.bat`，看 `DONEVAL=00004e84` |
| 看代码 / 看波形 / 看综合结构 | `source scripts/create_project.tcl`，开 Vivado |
| 烧到 Kosmo 板子上 | PDS 建工程 → 转引脚约束 → 跑流程 → 出 `top.sbit` → Program |
