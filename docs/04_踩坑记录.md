# 踩坑记录：14 个真实踩过的坑

> 这些坑全都是调试这套代码时**真实撞上**的，每一条都给出了报错原文、原因和修法。
> 如果你复刻时遇到类似现象，先来这里搜报错关键词。

---

## 坑 1：load 读回上一拍的旧数据（最隐蔽的 bug）

**现象**：程序跑到某条 `lw` 后 `jalr` 跳到 `0x12345688` 这种野地址，仿真直接跑飞。

**报错**：没有报错，就是结果错。

**原因**：

数据存储器 `DRAM.v` 的读口是**寄存器输出**（读有 1 拍延迟）：

```systemverilog
always @(posedge clk) begin
    if (we) mem[a] <= d;
    spo <= mem[a];        // ← 读也是打一拍
end
```

而 `cpu_LSU.sv` 里是这么写的：

```systemverilog
assign LSU_Rdata = rdata_ex;   // 当拍就把 rdata 交给 WB 级
```

于是 WB 级在时钟沿采样到的，是**上一个地址**的数据。只要地址一跳变，读回来的就是垃圾。

**修法**：把**读地址提前到 EX 级**算好，让 BRAM 的 1 拍延迟正好被 MEM 级吃掉。

`dram_driver.sv`：

```systemverilog
assign dram_addr = dram_wen ? perip_addr[17:2]    // 写：用 MEM 级地址
                            : rd_addr[17:2];      // 读：用 EX 级地址
```

配套改动 4 个文件：

- `dram_driver.sv`：新增 `rd_addr` / `rd_offset` 端口，读路径改用它
- `perip_bridge.sv:29`：加 `input logic [31:0] rd_addr`，例化时 `.rd_addr (rd_addr[17:0])`
- `cpu_myCPU.sv:44`：加 `output [31:0] perip_rd_addr`
- `cpu_myCPU.sv` 末尾：

```systemverilog
assign perip_rd_addr = (EXU_mem_ren === 1'b1) ? EXU_Ex_result : 32'h8010_0000;
```

用 `===` 和"安全地址"，是为了防止无效的 X 值扩散到 BRAM 地址端口（否则仿真里 PC 会变成 X）。

**教训**：存储器的读延迟一定要数清楚。写"1 拍"的时候，要明确是"地址发出后 1 拍数据有效"，还是"时钟沿后 1 拍"。

## 坑 2：`add` 模块接线接反 + always 里给 wire 赋值

**现象**：语法检查报错，`cpu_ALU.sv` 整个模块被忽略。

**报错原文**：

```
ERROR: [VRFC 10-1280] procedural assignment to a non-register result is not permitted,
left-hand side should be reg/integer/time/genvar [C:/temp/chk/cpu_ALU.sv:95]
ERROR: [VRFC 10-8530] module 'ALU' is ignored due to previous errors
```

**原因有两个**：

1. `cpu_add.sv` 里的 `add_2_inv` 是**输入**端口，不是输出：

```systemverilog
module add #(BW = 4) (
    input  choose_add_sub,
    input  [BW-1:0] add_1,
    input  [BW-1:0] add_2,
    input  [BW-1:0] add_2_inv,   // ← 输入！调用方算好取反送进来
    output [BW-1:0] result
);
```

所以外部必须自己算 `d2_inv = ~d2`：

```systemverilog
logic [BW-1:0] d2_inv;
assign d2_inv = ~d2;

add #(.BW(BW)) add_inst0 (
    .choose_add_sub(choice == `alu_sub),
    .add_1(d1), .add_2(d2), .add_2_inv(d2_inv),
    .result(add_result)
);
```

2. `output [BW-1:0] result` 是 wire，在 `always @(*)` 里赋值必须是 `output logic`：

```systemverilog
// 错
output [BW-1:0] result
always @(*) result = ...;        // ← 报 VRFC 10-1280

// 对
output logic [BW-1:0] result
always @(*) result = ...;
```

**教训**：Verilog 里 `output` 默认是 wire，过程赋值必须加 `logic`/`reg`。

## 坑 3：PDS 综合器不允许大 for 循环

**现象**：PDS 综合直接报错退出，Vivado 却没事。

**报错原文**：

```
E: Verilog-4092: [D:/.../rtl/DRAM.v(line number: 12)] Loop limit 2000 exceeded.
```

**原因**：`DRAM.v` 里有这么一段：

```systemverilog
integer i;
initial begin
    for (i = 0; i < 65536; i = i + 1) mem[i] = 32'd0;   // ← 65536 次，超限
end
```

PDS 综合器限制循环展开次数 2000。

**修法**：综合版删掉大循环，只保留显式初值：

```systemverilog
initial begin
    mem[16'h0003] = 32'h1234abcd;
    mem[16'h0004] = 32'h55667788;
    mem[16'h0007] = 32'hff0000ff;
end
```

Pango 的 BRAM 上电就是 0，所以删掉循环不影响硬件行为；但**仿真必须保留**（xsim 不会自动清零）。

**教训**：硬件描述里的 `initial` 块，综合器和仿真器的理解经常不一样。要么两边都写，要么用 `$readmemh`。

## 坑 4：`.sv` 文件被当成 Verilog-2001 编译

**现象**：PDS 编译 `.sv` 文件报一堆语法错。

**报错原文**：

```
E: Verilog-4039: [D:/.../cpu_myCPU.sv(line number: 62)] Identifier 'logic' is not declared.
```

**原因**：PDS 默认按 Verilog-2001 编译，不认 SystemVerilog 的 `logic` 关键字。

**修法**：综合选项加 `-verilog_standard SystemVerilog`：

```tcl
compile -verilog_standard SystemVerilog -top_module top
```

**教训**：`.sv` 后缀不代表工具会自动按 SV 编译，要显式指定。

## 坑 5：顶层有端口没约束

**现象**：PDS 在 `Device Map` 阶段报 12 个错。

**报错原文**：

```
E: ConstraintEditor-0099: Port 'uart_tx8' unspecified I/O constraint.
```

**原因**：`top.v` 里还留着调试用的镜像端口 `uart_tx2` ~ `uart_tx13`（当时想试试哪根脚能出数据），但 `kosmo_pins.fdc` 里只有 `uart_tx` 一条约束。

**修法**：删掉 `top.v` 里所有 `uart_tx2..uart_tx13` 的端口声明和 `assign`，顶层只留 4 个端口：

```systemverilog
module top (
    input  wire        clk,      // T9  50 MHz
    input  wire        rst_n,    // W13 按键
    output wire [7:0]  led,      // G14/E18/E19/F16/F17/H18/E17/H15
    output wire        uart_tx   // W6
);
```

同时删掉 xdc/fdc 里对应的约束行（否则 Vivado 会报 `[Common 17-55] 'set_property' expects at least one object`）。

**教训**：调试用的临时端口一定要清理干净，否则约束文件会跟着改，最后两边都对不上。

## 坑 6：Vivado 综合报位宽越界

**现象**：Vivado 综合失败（PDS 却通过了）。

**报错原文**：

```
ERROR: [Synth 8-524] part-select [39:0] out of range of prefix 'seg_wdata' [perip_bridge.sv:91]
ERROR: [Synth 8-6156] failed synthesizing module 'perip_bridge' [perip_bridge.sv:23]
```

**原因**：端口是 40 位，内部变量是 32 位：

```systemverilog
output logic [39:0] virtual_seg_output,   // 40 位
logic [31:0] seg_wdata;                   // 32 位
assign virtual_seg_output = seg_wdata;    // 39:0 越界
```

**修法**：把内部变量也扩到 40 位：

```systemverilog
logic [39:0] seg_wdata;
seg_wdata <= {8'd0, perip_wdata};         // 写的时候补高 8 位
assign virtual_seg_output = seg_wdata;
mmio_rdata = seg_wdata[31:0];             // 读的时候只取低 32 位
```

**教训**：PDS 对位宽比较宽容（自动截断/补零），Vivado 很严格。**换工具链之前先按严格的那边检查一遍**。

## 坑 7：例化了模块没有的端口

**现象**：Vivado 综合报错。

**报错原文**：

```
ERROR: [Synth 8-11365] for the instance 'dram_driver_inst' of module 'dram_driver' declared at
'D:/kosmo_vivado/rtl/dram_driver.sv:22', named port connection 'rst' does not exist
[perip_bridge.sv:123]
```

**原因**：`perip_bridge.sv` 例化 `dram_driver` 时连了 `.rst(rst)`，但 `dram_driver` 根本没有 `rst` 端口。

**修法**：删掉那行 `.rst(rst),`，同时把写错的端口名改回来：

```systemverilog
// 错
.dram_rdata (dram_rdata)

// 对（模块里叫 perip_rdata）
.perip_rdata (dram_rdata)
```

**教训**：改模块端口之后，所有例化处都要搜一遍。

## 坑 8：PowerShell 读 UTF-8 文件变乱码

**现象**：用 `Get-Content` 看源码，中文注释全是乱码，而且行数不对。

**原因**：PowerShell 5.1 的 `Get-Content` 默认按系统 ANSI 编码（中文系统是 GBK）解码。UTF-8 的中文被按 GBK 读，就成了乱码；某些字节组合还会被当成换行，导致行数错乱。

**修法**：

```powershell
Get-Content file.sv -Encoding UTF8      # 读
Set-Content file.sv -Encoding UTF8      # 写
```

或者用 `read` 工具（如果用的是 DSH/Claude Code 这类工具）。

**教训**：跨工具传中文，一定要显式指定编码。判断"文件是不是坏了"之前，先确认**读取方式**对不对。

## 坑 9：双引号里的反引号被当成转义符

**现象**：写了个脚本给 Verilog 文件加 `` `timescale ``，结果文件第一行变成 `\timescale`，编译报 `syntax error near '1ns'`。

**原因**：PowerShell 双引号字符串里，反引号 `` ` `` 是转义字符。`` "`timescale" `` 里的 `` `t `` 被解释成 TAB（`\t`）。

**修法**：

```powershell
# 错
"`timescale 1ns/1ps"

# 对
[char]0x0060 + "timescale 1ns/1ps"
# 或者用单引号（单引号里不转义）
'`timescale 1ns/1ps'
```

**教训**：把 `` ` `` 当成普通字符，用单引号或 `[char]0x0060`。

## 坑 10：bat 文件里的中文变成 `??????`

**现象**：写了个 `.bat` 给同学用，里面写中文提示，对方双击后全是 `??????`。

**原因**：cmd 默认用系统 ANSI 代码页（中文系统是 936/GBK），而 bat 文件存的是 UTF-8。`chcp 936` 也不管用（因为文件本身就是 UTF-8 字节流）。

**修法**：**bat 里只写 ASCII 英文**，中文说明放到 README.md 里。

```bat
@echo off
echo === RISC-V CPU Simulation ===
echo Running xvlog / xelab / xsim ...
```

**教训**：给不确定环境的机器写批处理，只写 ASCII。

## 坑 11：xsim 报 timescale 不一致

**现象**：`xvlog` 编译通过，`xelab` 报错。

**报错原文**：

```
ERROR: [XSIM 43-4099] "C:/temp/cpusim/cpu_myCPU.sv" Line 62. Module myCPU doesn't have a
timescale but at least one module in design has a timescale.
```

**原因**：27 个源文件里，只有 5 个写了 `` `timescale 1ns/1ps ``（`counter.sv`、`dram_driver.sv`、`perip_bridge.sv`、`top.v`、`uart.sv`），其余 21 个没写。Verilog 要求"要么全有、要么全没有"。

**修法**：给所有文件第一行都加上：

```verilog
`timescale 1ns/1ps
```

**教训**：多文件工程，`timescale` 要么统一加要么统一不加。

## 坑 12：PowerShell 不展开通配符

**现象**：

```powershell
xvlog -sv ../rtl/*.sv tb.sv
```

报 `ERROR: [XSIM 43-4316] Can not find file: *.sv`。

**原因**：PowerShell 不像 bash 那样把 `*.sv` 展开成文件列表再传给程序（`xvlog.bat` 是外部程序，拿到的就是字面量 `*.sv`）。

**修法**：

```powershell
$files = @(Get-ChildItem ../rtl/*.sv, ../rtl/*.v | ForEach-Object { $_.FullName })
xvlog -sv @files tb.sv
```

`@files` 会把数组展开成多个参数。

**教训**：PowerShell 里调用外部程序时，通配符必须自己展开。

## 坑 13：Vivado 路径带空格被撕开

**现象**：`vivado.bat -mode batch -source xxx.tcl` 报：

```
ERROR: [Vivado 12-172] File or Directory 'D:/ZI' does not exist
```

**原因**：工程路径是 `D:\ZI          GUANG\aaaaidearjiyeda\rs0\...`（`ZI` 和 `GUANG` 之间有 10 个空格）。Vivado 的 Tcl 解析这段路径时，把空格当成了参数分隔符，于是只拿到 `D:/ZI`。

**修法**：把要交给 Vivado 的文件放到**无空格路径**下：

```
D:\kosmo_vivado\rtl\        （27 个源文件）
D:\kosmo_vivado\constrs\    （xdc）
D:\kosmo_vivado\kosmo_rtl\  （工程目录）
```

**教训**：EDA 工具对带空格的路径普遍不友好。工程目录一律用纯英文无空格。

## 坑 14：PDS 烧录报链上器件不匹配

**现象**：点 `Program` 之后报错，位流没烧进去。

**报错原文**：

```
E: Configuration-0013: PU at location 0 has no bitstream file, please assign the bitstream file.
E: Configuration-0003: The bitstream file doesn't match the device. The current device is 'PU',
but the device info in the bitstream file is 'PG2K100'.
E: JtagServer-0308: The count of devices added to the JTAG chain does not match the hardware.
```

**原因有三个，经常同时出现**：

1. JTAG 链上扫出两个器件：`Arm-PU` 和 `Kosmo2-PG2K100`。位流只能烧给 **PG2K100**，但工具默认操作了 PU。
2. 手动 `Add Pango Device` 加的设备，和实际硬件对不上，导致"数量不匹配"。
3. 位流是给 PG2K100 编译的，却指定给了 PU。

**修法**：

1. 先 `Scan Device`（**不要手动 Add Device**），让工具自己扫出真实链
2. 右键 `Kosmo2-PG2K100` → `Assign New Configuration File` → 选 `top.sbit`
3. 右键同一个器件 → `Program`（**不要用工具栏的全局 Program**）

**成功标志**：

```
[2026.11.09 21:23:30] Finish program D:/.../top.sbit
The done bit is 1
```

**教训**：多器件 JTAG 链上，一定要**对具体器件操作**，不要用全局命令。

## 附：这些坑的共同规律

| 规律 | 对应坑 |
|---|---|
| 存储器的读延迟必须数清楚 | 1 |
| Verilog 的 `output` 默认是 wire | 2 |
| 综合器对 `initial` / 循环的理解和仿真器不同 | 3 |
| `.sv` 后缀 ≠ 按 SV 编译 | 4 |
| 临时调试端口要清理干净 | 5、6 |
| 改端口后要全局搜例化处 | 7 |
| 跨工具传中文必须显式指定编码 | 8、9、10 |
| 多文件工程 `timescale` 必须统一 | 11 |
| 外部程序的通配符要自己展开 | 12 |
| EDA 工具怕空格 | 13 |
| 多器件链要对具体器件操作 | 14 |
