# 27 个文件逐个详解

> 这份文档的目标：**不打开代码也能知道每个文件在干什么；打开代码能知道每一段为什么这么写。**
>
> 阅读顺序建议：`cpu_para.sv` → `cpu_Reg.sv` → `cpu_add.sv` → `cpu_sext.sv` → `cpu_ALU.sv`
> → `cpu_RegisterFile.sv` → `cpu_CSR.sv` → `cpu_Reg_Stack.sv` → `cpu_IFU.sv` → `cpu_IDU.sv`
> → `cpu_IFID_EX_Reg.sv` → `cpu_EXU.sv` → `cpu_Data_hazard.sv` → `cpu_Control.sv`
> → `cpu_EX_LSWB_Reg.sv` → `cpu_LSU.sv` → `cpu_WBU.sv` → `cpu_myCPU.sv`

---

## 一、基础积木（5 个）

### 1. `rtl/cpu_para.sv` —— 全局宏定义

**作用**：把 opcode 和 ALU 操作码定义成宏，全项目共用一份。

**内容**：

```systemverilog
`define R_opcode  7'b0110011   // 寄存器-寄存器运算（add/sub/and/or/xor/sll/srl/sra/slt/sltu）
`define lw        7'b0000011   // 取字（load）
`define addi      7'b0010011   // 立即数运算（addi/andi/ori/xori/slli/srli/srai）
`define jarl      7'b1100111   // 间接跳转（jalr）
`define S_opcode  7'b0100011   // 存储（sw）
`define B_opcode  7'b1100011   // 条件分支（beq/bne/blt/bge）
`define lui       7'b0110111   // 装载高位立即数
`define auipc     7'b0010111   // PC + 高位立即数
`define jal       7'b1101111   // 直接跳转
`define M_opcode  7'b1110011   // CSR / ecall / mret
```

ALU 操作码是 4 位：`alu_add/sub/or/and/xor/signed_comparator/unsigned_comparator/equal/sll/srl/sra`。

**复刻要点**：这些宏在每个 `.sv` 文件头都重复写了一遍，是为了「单个文件拿出来也能编译」。重复定义只会产生 warning，不影响综合。

---

### 2. `rtl/cpu_Reg.sv` —— 通用寄存器（16 行）

**作用**：一个带复位、带写使能的 D 触发器组。所有流水寄存器都用它的行为模式写的。

**端口**：`clock`、`reset`、`wen`、`din`、`dout`、参数 `WIDTH` / `RESET_VAL`。

**核心就三行**：

```systemverilog
always @(posedge clock) begin
    if (reset)       dout <= RESET_VAL;   // 复位值可配（默认 0）
    else if (wen)    dout <= din;         // 只有 wen 才更新
end
```

**为什么单独抽出来**：五级流水里有 5 个位置要存 PC（IF、ID、EX、MEM、WB），全部复用这一个模块，避免复制粘贴出错。

---

### 3. `rtl/cpu_add.sv` —— 加减法器（30 行）

**作用**：ALU 内部的 32 位加/减。

**端口**：`choose_add_sub`（0 加 1 减）、`add_1`、`add_2`、`add_2_inv`、`result`。

**关键两行**：

```systemverilog
assign add_3 = (choose_add_sub == 1'b0) ? add_2 : (add_2_inv + 1'b1);  // 减法 = 取反加一
assign result = add_1 + add_3;
```

**为什么不用 `-` 运算符**：要显式地教「补码减法」这件事，也方便以后换成超前进位加法器。

**注意**：`add_2_inv` 是**输入**！调用方要传 `~add_2` 进来，不是让它输出。这是第一次写注释时踩过的坑（见 `docs/04`）。

---

### 4. `rtl/cpu_sext.sv` —— 符号扩展（16 行）

**作用**：把 8 位或 16 位数据符号扩展到 32 位。`lb`/`lh` 指令要用。

**核心一行**：

```systemverilog
assign sext_data = {{(OUT_WIDTH-DATA_WIDTH){data[DATA_WIDTH-1]}}, data};  // 高位全补符号位
```

**例**：`data = 8'h80`（-128）→ 扩展后 `32'hFFFF_FF80`。

---

### 5. `rtl/cpu_ALU.sv` —— 算术逻辑单元（107 行）

**作用**：吃两个 32 位数 + 4 位操作码，吐一个 32 位结果。

**做法**：先把所有可能用到的中间结果**并行算出来**，最后用 `case` 选一个。

```systemverilog
// 预计算（全部同时算，综合器会自动共享/裁掉没用的）
assign and_result = d1 & d2;
assign or_result  = d1 | d2;
assign xor_result = d1 ^ d2;
assign sll_result = d1 << d2[4:0];        // 移位量只取低 5 位（RV32I 规定）
assign srl_result = d1 >> d2[4:0];
assign sra_result = $signed(d1) >>> d2[4:0];
assign signed_lt   = ($signed(d1) < $signed(d2)) ? 1'b1 : 1'b0;
assign unsigned_lt = (d1 < d2) ? 1'b1 : 1'b0;
assign equal       = (d1 != d2) ? 1'b1 : 1'b0;   // 注意：这是"不相等"

// 加减走子模块
add add_inst0(.choose_add_sub(choice == `alu_sub), .add_1(d1), .add_2(d2),
              .add_2_inv(d2_inv), .result(add_result));

// 选择
case (choice)
    `alu_add: result = add_result;
    `alu_sub: result = add_result;   // 减法已经在 add 模块里做完了
    `alu_and: result = and_result;
    ...
    `alu_equal: result = {{(BW-1){1'b0}}, equal};
endcase
```

**`equal` 为什么定义成"不相等"**：配合 EX 级的取反技巧，`beq` 时把结果 bit0 翻一下就变成"相等"。见 `cpu_EXU.sv`。

## 二、寄存器与 CSR（3 个）

### 6. `rtl/cpu_RegisterFile.sv` —— 32×32 寄存器堆（66 行）

**作用**：RV32I 的 x0~x31。

**端口**：两个**组合**读口（`rs1_addr→rs1_value`、`rs2_addr→rs2_value`）、一个**同步**写口（`wen/waddr/wdata`）、`a0_value` 单独引出。

**三条规则**：

```systemverilog
// 1) 写口：x0 永不写
always @(posedge clock) begin
    if (reset)                 for (...) rf[i] <= 0;
    else if (wen && waddr != 0) rf[waddr] <= wdata;
end

// 2) 读口：组合，不花周期
assign rs1_value = (rs1_addr == 0) ? 0 : rf[rs1_addr];
assign rs2_value = (rs2_addr == 0) ? 0 : rf[rs2_addr];

// 3) a0 = x10 单独引出，测试程序把结果放这
assign a0_value = rf[10];
```

**为什么读口是组合的**：RISC-V 规定寄存器读不占周期，ID 级当拍就要拿到数。

**为什么 x0 要"双保险"**：写口挡一次、读口再挡一次，防止有人绕过写口把它写脏。

---

### 7. `rtl/cpu_CSR.sv` —— CSR 寄存器组（94 行）

**作用**：实现四个可写的 CSR + 两个只读 ID。

| 地址 | 名字 | 用途 |
|---|---|---|
| `0x341` | mepc | 异常返回地址 |
| `0x342` | mcause | 异常原因 |
| `0x300` | mstatus | 状态（复位值 `0x1800`，MPP=11） |
| `0x305` | mtvec | 异常入口地址 |
| `0xF11` | mvendorid | 只读，我们填 `0x79737978`（"ysyx"） |
| `0xF12` | marchid | 只读，填 `0x16FBCBD` |

**核心赋值**：

```systemverilog
assign mepc_in   = (ecall_flag | (|exc_cause)) ? pc : csrd;
assign mcause_in = (exc_cause == 2'b10) ? 32'd1 :     // 取指异常
                   (exc_cause == 2'b01) ? 32'd0 :     // 地址不对齐
                   (ecall_flag)         ? 11 : csrd;  // ecall
```

**局限（要如实说）**：只有陷入通路，没有异常处理程序；`mtvec` 复位为 0，真异常会跳到 0 死循环。竞赛题目不要求异常，所以不影响。

---

### 8. `rtl/cpu_Reg_Stack.sv` —— 寄存器堆 + CSR 的壳（73 行）

**作用**：把 `RegisterFile` 和 `CSR` 打包成一个模块，ID 级只要例化这一个。

**内部**：两个子模块 + 一段 CSR 地址译码：

```systemverilog
assign csrs = (csr_addr == 32'h341) ? mepc_out :
              (csr_addr == 32'h342) ? mcause_out :
              (csr_addr == 32'h300) ? mstatus_out :
              (csr_addr == 32'h305) ? mtvec_out : ... ;
assign wdata = (rd == 4'd0) ? 32'd0 : rd_value;   // 写 x0 无效
```

## 三、五级流水线本体（7 个）

### 9. `rtl/cpu_IFU.sv` —— IF 级：取指（81 行）

**作用**：维护 PC，把 PC 送去指令 ROM，拿回指令。

**端口**：`clock`、`reset`、`dnpc`（跳转目标）、`dnpc_flag`（跳不跳）、`irom_data`（ROM 回来的指令）、`stall`、`snpc`、`pc`、`inst`、`ifault`。

**PC 更新逻辑（四优先级）**：

```systemverilog
always @(posedge clock) begin
    if (reset)                          pc <= 32'h8000_0000;      // ① 复位
    else if (stall && valid && ready)   pc <= pc;                 // ② 停顿：保持
    else if (dnpc_flag && valid && ready) pc <= dnpc;             // ③ 跳转：跳
    else                                pc <= snpc;               // ④ 正常：+4
end
assign snpc = pc + 32'd4;
assign inst = irom_data;
```

**`ifault` 是干什么的**：`assign ifault = (pc[31:14] != 18'h2_0000);`
PC 跑出 `0x8000_0000~0x8000_FFFF` 就认为非法。这条线是当年调试"程序跑飞"时加的探针，现在留着当保险。

---

### 10. `rtl/cpu_IDU.sv` —— ID 级：译码（207 行，最大的一块）

**作用**：拿到 32 位指令，拆出 opcode/rd/funct3/rs1/rs2，生成所有控制信号、立即数、分支目标。

**输入**：`inst`、`snpc`、`pc`、`EXU_rs1_in`/`EXU_rs2_in`（**旁路后的操作数**）、`rd_value`（写回值）

**输出**：一长串控制 + 数据，交给 ID/EX 寄存器。

**六种立即数格式**（这是 RISC-V 最反直觉的地方，必须写对）：

```systemverilog
imm_I = {{20{inst[31]}}, inst[31:20]};                                  // addi/lw/jalr
imm_U = {inst[31:12], 12'd0};                                           // lui/auipc
imm_S = {{20{inst[31]}}, inst[31:25], inst[11:7]};                      // sw
imm_B = {imm_S[31:11], imm_S[0], imm_S[10:1]} << 1;                    // 分支（位序被打乱！）
imm_J = {{11{inst[31]}}, inst[31], inst[19:12], inst[20], inst[30:21]} << 1;  // jal（更乱）
imm_R = {25'd0, inst[31:25]};                                           // 移位量
```

**分支目标**：`assign branch_pc = pc + imm;`

**`inv_flag` 是什么**：

```systemverilog
assign inv_flag = (opcode == `B_opcode) && (funct3 == 3'b101 || funct3 == 3'b111 || funct3 == 3'b000);
```

`bge`(101)、`bgeu`(111)、`beq`(000) 这三个分支，判定条件和 ALU 的默认比较方向相反，于是让 ALU 算完取反。EX 级用 `alu_result ^ inv_flag` 一行搞定，省掉一条比较器。

**操作数选择**（`add1_value`/`add2_value`）：

```systemverilog
assign add1_value = (opcode == `lui) ? 32'd0
                  : (opcode == `jal || opcode == `auipc) ? pc
                  : EXU_rs1_in;                        // 默认用旁路后的 rs1
assign add2_value = (opcode == `R_opcode || opcode == `B_opcode) ? EXU_rs2_in
                  : (opcode == `lw && funct3 == 3'b010) ? rd_value_next
                  : (opcode == `lw && funct3 == 3'b001) ? 32'd0
                  : imm;
```

**写回值预选**：

```systemverilog
assign rd_value_next = jump_flag ? snpc                    // jal/jalr 写 PC+4
                     : (|csr_wen_next) ? csrs              // CSR 指令写 CSR 值
                     : 32'd0;
```

---

### 11. `rtl/cpu_IFID_EX_Reg.sv` —— ID/EX 流水寄存器（150 行）

**作用**：五级流水中间那道"墙"。ID 拍出来的所有信号，锁到 EX 拍用。

**三类信号**：

1. `valid_next`：这一拍里有没有真指令
2. 数据寄存器：`funct3 / rd / alu_opcode / inv_flag / rs2_value / add1 / add2 / rd_value / branch_pc / pc`
3. **控制寄存器**：`mem_ren / csr_wen / R_wen / mem_wen / jump_flag / branch_flag / fetch_i`

**更新条件**：

```systemverilog
// valid：被冲刷就清，否则跟着上一级
always @(posedge clock) begin
    if (reset)                                    valid_next <= 0;
    else if (valid_last & ready_next & EXU_inst_clr) valid_next <= 0;   // 冲刷
    else if (valid_last & ready_next)             valid_next <= 1;
    else                                          valid_next <= 0;
end

// 数据/控制：只有 valid & ready 才更新
always @(posedge clock) begin
    if (valid_last & ready_next) begin
        R_Wen_next <= R_wen_last;    // 等等
        ...
    end
    if (reset) R_Wen_next <= 0;      // 复位时控制位必须清 0
end
```

**为什么控制位要单独清 0**：如果只清 `valid` 不清控制位，被冲刷的指令在后面的级里仍然带着 `R_wen=1`，会写坏寄存器堆 —— 这叫"幽灵写回"。`cpu_WBU.sv` 里 `R_wen_next = R_wen & valid` 是第二道保险。

---

### 12. `rtl/cpu_EXU.sv` —— EX 级：执行（90 行）

**作用**：调 ALU 算结果，算出分支是否成立、跳转目标。

**核心一行（取反技巧）**：

```systemverilog
assign Ex_result = alu_result ^ {31'd0, inv_flag_reg};
```

`beq` 时 `inv_flag=1`，ALU 的 `equal`（不相等）翻一下就是"相等"。省一条 32 位比较器。

**其余全是透传**：13 条 `assign xxx_next = xxx_reg;`，把信号原样送到 MEM 级。

---

### 13. `rtl/cpu_EX_LSWB_Reg.sv` —— EX/MEM 流水寄存器（112 行）

**作用**：EX 拍的结果锁到 MEM 拍。

**端口**：11 个寄存器输入输出：`mem_ren / mem_wen / R_wen / csr_wen / Ex_result / rd / funct3 / rs2_value / jump_flag / rd_value / pc`。

**和 IFID_EX_Reg 的差别**：这里 `valid_next` 只看 `valid_last & ready_last`，**不看 `ready_next`**（因为 WB 级永远 ready）。

---

### 14. `rtl/cpu_LSU.sv` —— MEM 级：访存（91 行）

**作用**：把地址、写数据、写使能、字节掩码送出去；把读回来的数据按 `funct3` 做符号/零扩展。

**核心**：

```systemverilog
assign addr  = Ex_result_reg;      // 访存地址就是 ALU 算出来的
assign wdata = rs2_value_reg;      // 要写的数据
assign wen   = mem_wen_reg;
assign mask  = funct3_reg[1:0];    // 00=1字节 01=2字节 10=4字节

case (funct3_reg)
    3'b000: rdata_ex = rdata_8i;    // lb  符号扩展
    3'b001: rdata_ex = rdata_16i;   // lh
    3'b010: rdata_ex = rdata;       // lw
    3'b100: rdata_ex = rdata_8u;    // lbu 零扩展
    3'b101: rdata_ex = rdata_16u;   // lhu
    default: rdata_ex = 32'd0;
endcase
```

---

### 15. `rtl/cpu_WBU.sv` —— WB 级：写回（91 行）

**作用**：选一个值写回寄存器堆。**纯组合，没有寄存器**。

**核心一行（优先级口诀：跳转/CSR > load > ALU）**：

```systemverilog
assign rd_value_next = (jump_flag | (|csr_wen)) ? rd_value
                     : (mem_ren)                ? MEM_Rdata
                     :                             Ex_result;
```

**防幽灵写回**：

```systemverilog
assign R_wen_next = R_wen & valid;    // 被冲刷的指令不许写
```

## 四、控制中枢（2 个）

### 16. `rtl/cpu_Data_hazard.sv` —— 冒险检测（38 行）

**作用**：判断"EX 要用的寄存器是不是刚被前一条指令写过"，输出旁路选择码。

**两个判断**：

```systemverilog
assign exu_rs1_match = (EXU_rd == IDU_rs1) && (EXU_rd != 5'b0);   // 比 rd，但忽略 x0
assign mem_rs1_match = (MEM_rd == IDU_rs1) && (MEM_rd != 5'b0);
assign exu_rs1_valid = EXU_R_Wen && exu_rs1_match;                 // 还得真的写
assign mem_rs1_valid = MEM_R_Wen && mem_rs1_match;
```

**四档选择码**：

```systemverilog
assign IDU_rs1_choice = exu_rs1_valid ? 2'b01                    // EX 结果最新
                      : (mem_rs1_valid ? (MEM_mem_ren ? 2'b11 : 2'b10)  // load 数据 / MEM 结果
                      : 2'b00);                                   // 用寄存器堆原值
```

| 码 | 含义 |
|---|---|
| `2'b00` | 用寄存器堆读出来的值 |
| `2'b01` | 用 EX 级刚算出来的 `Ex_result` |
| `2'b10` | 用 MEM 级的 `Ex_result`（上一拍的 EX 结果） |
| `2'b11` | 用 MEM 级 load 回来的数据 |

**为什么 EX 优先于 MEM**：EX 的结果比 MEM 新，两个都是同一条 rd 时应该用新的。

---

### 17. `rtl/cpu_Control.sv` —— 全 CPU 的交通警察（143 行）

**作用**：整个 CPU 唯一集中做决策的地方。纯组合，无状态。输出四类东西：

1. **旁路值**：`EXU_rs1_in` / `EXU_rs2_in`（用 `IDU_rs1_choice` 四选一）
2. **停顿**：`IFU_stall`
3. **冲刷**：`dnpc` / `dnpc_flag` / `EXU_inst_clear`
4. **异常**：`exc_cause`

**分支与跳转判定**：

```systemverilog
assign branch_taken     = branch_flag & Ex_result[0];        // ALU 结果 bit0 = 1 就是成立
assign exception_or_jump = jump_flag | fence_i_flag | mret_flag | ecall_flag;
```

**陷阱判定**：

```systemverilog
assign exc_misalign = ~mret_flag & ~ecall_flag &
                      ((jump_flag & Ex_result[1]) | (branch_taken & branch_pc[1]));
assign exc_trap  = exc_misalign | ifault;
assign exc_cause = ifault ? 2'b10 : (exc_misalign ? 2'b01 : 2'b00);
```

**load-use 停顿**：

```systemverilog
assign stall_condition = EXU_mem_ren && (rs1_hazard || rs2_hazard);
assign IFU_stall       = stall_condition;
```

这条只有一行，但它决定了 `lw` 后面紧跟用该数据时必须停一拍。

**下一条指令地址（五级优先）**：

```systemverilog
always @(*) begin
    if (exc_trap)     dnpc_next = mtvec_out;     // ① 异常
    else if (jump_flag) dnpc_next = Ex_result;   // ② jal/jalr
    else if (branch_flag) dnpc_next = branch_pc; // ③ 条件分支
    else if (mret_flag) dnpc_next = mepc_out;    // ④ 返回
    else              dnpc_next = mtvec_out;
end
```

**冲刷信号**：

```systemverilog
assign dnpc_flag      = branch_taken | exception_or_jump | exc_trap;
assign EXU_inst_clear = branch_taken | exception_or_jump | stall_condition | exc_trap;
```

## 五、CPU 顶层（1 个）

### 18. `rtl/cpu_myCPU.sv` —— 把五级连起来（463 行）

**作用**：**只做连线，不写逻辑**。7 个子模块例化 + 8 组信号声明。

**例化顺序（信号流向）**：

```systemverilog
IFU  u_ifu  (.pc(irom_addr), .inst(IFU_inst), ...);
IDU  u_idu  (.inst(IFU_inst), .rs1_value(...), ...);
IFID_EX_Reg u_ifid_ex (.valid_last(IFU_valid), ...);      // ← 第一道墙
EXU  u_exu  (...);
EX_LSWB_Reg u_ex_lswb (.valid_last(IFID_EX_valid), ...);  // ← 第二道墙
LSU  u_lsu  (...);
WBU  u_wbu  (...);        // 输出回 IDU 的 rd_value / R_wen
Control u_ctl (...);      // 连到所有级
Data_hazard u_dh (...);   // 被 Control 例化
Reg_Stack u_rf (...);     // 被 IDU 例化
```

**结尾那行修复（重要）**：

```systemverilog
// DRAM 读是 1 拍寄存输出，所以读地址必须提前到 EX 级给出
assign perip_rd_addr = (EXU_mem_ren === 1'b1) ? EXU_Ex_result : 32'h8010_0000;
```

用 `===` 而不是 `==`，是因为 `EXU_Ex_result` 在没有访存时可能是 X，X 进 BRAM 地址会让整个仿真变 X。

## 六、板级与外设（9 个）

### 19. `rtl/top.v` —— 板级顶层（13.5 KB）

**作用**：CPU + 指令 ROM + 数据通路 + 外设桥 + 串口发帧，全在这一个文件里连起来。

**四个端口**（对应板子上的引脚）：

```systemverilog
module top (input wire clk,        // 50 MHz 晶振 T9
            input wire rst_n,      // BTN0，低有效 W13
            output wire [7:0] led, // 8 个 LED
            output wire uart_tx);  // 串口发送 W6
```

**内部三件事**：

1. 复位同步：`rst_n` 是异步按键，要打两拍同步到时钟域
2. 连 CPU：`myCPU` + `IROM` + `perip_bridge`（内部含 DRAM 驱动）
3. `ms_uart_tx`：每 0.5 秒把 32 位毫秒值打包成 6 字节发出去

**串口帧格式**（自己定的，方便 PC 端解析）：

```
字节 0: 0xAA           帧头
字节 1~4: 毫秒值（大端，最高字节先发）
字节 5: 前 5 字节异或  校验
```

`DIV = (50_000_000 + 115200/2) / 115200 = 434`，用四舍五入而不是截断，波特率误差约 0.006%。

---

### 20. `rtl/IROM.v` —— 指令 ROM（85 KB）

**作用**：16 位地址、32 位宽的单口 ROM，内部用 `$readmemh` 预装程序。

**为什么这么大**：它是 16384 × 32 位 = 64 KB，综合成 64 个 BRAM36。

**组合读**：`assign inst = mem[addr[15:2]];`，不给时钟。竞赛题目也要求"指令 ROM 组合读"。

---

### 21. `rtl/DRAM.v` —— 数据 RAM（616 B）

**作用**：16 位地址、32 位宽的双口 RAM（一读一写）。

**关键（也是当年 bug 的源头）**：

```systemverilog
always @(posedge clk) begin
    if (we) mem[a] <= d;
    spo <= mem[a];        // ← 读数据是"寄存输出"，比地址晚一拍
end
```

读地址给进去，数据要**下一拍**才出来。LSU 原本当拍就用，于是读到的是上一个地址的数据 —— 这是整个项目最隐蔽的 bug。修法见 `dram_driver.sv`。

---

### 22. `rtl/dram_driver.sv` —— DRAM 读写驱动（94 行）

**作用**：把 DRAM 的"1 拍延迟"包起来，并且在读写之间做地址选择。

**核心两行**：

```systemverilog
// 写：MEM 级的地址（正常）
// 读：EX 级的地址（提前一拍给出去）
assign dram_addr = dram_wen ? perip_addr[17:2] : rd_addr[17:2];
```

**为什么读地址要提前到 EX 级**：EX 拍把地址给 DRAM，DRAM 在 EX→MEM 那一拍把数据锁好，MEM 拍正好用 —— 零成本补齐这一拍。

---

### 23. `rtl/perip_bridge.sv` —— 外设桥（132 行）

**作用**：地址译码 + 数据宽度处理。CPU 通过它访问 RAM 和所有外设。

**地址映射**：

| 地址范围 | 设备 | 说明 |
|---|---|---|
| `0x8010_0000 ~ 0x8013_FFFF` | DRAM | 64 KB 数据存储器 |
| `0x8020_0000 / 0x8020_0004` | SW0 / SW1 | 拨码开关 |
| `0x8020_0010` | KEY | 按键 |
| `0x8020_0020` | SEG | 数码管段码 |
| `0x8020_0040` | LED | LED |
| `0x8020_0050` | CNT | 毫秒计数器 |
| 其它 | —— | 读回 `0xDEAD_BEEF` |

**写宽度处理**：`perip_mask` 决定写 1/2/4 字节，桥里用 `case` 拼出要写的字节。

---

### 24. `rtl/counter.sv` —— 毫秒计数器（74 行）

**作用**：数时钟周期，每 50000 个 = 1 ms。

```systemverilog
if (cnt_1ms == 49999) begin    // 50 MHz → 50000 个周期 = 1 ms
    cnt_1ms <= 0;
    cnt_ms  <= cnt_ms + 1;
end
```

**⚠️ 如果板子实际是 27 MHz**：把两处 `49999` 改成 `26999`（第 52、65 行）。
设计里写死 50 MHz，如果实际是 27 MHz，计时会**少报 46%**（真 30 秒只报 16.2 秒）。

**启动/停止**：写 `0x8000_0000` 到 CNT 地址开始计时，写 `0xFFFF_FFFF` 定住（定格）。

---

### 25. `rtl/uart.sv` —— 标准 UART（174 行）

**作用**：115200 8N1 的收发，可单独复用。

**收发各一个状态机**：

- 收：三级同步消抖 → 检测下降沿（起始位）→ 等半位对齐 → 每位采一次 → 8 位收完给 `rx_data`
- 发：`tx_shift <= {1'b1, tx_data, 1'b0}`（停止位|数据|起始位）→ 每次右移输出 bit0

**注意**：`top.v` 里实际用的是自己写的 `ms_uart_tx`（每 0.5 秒自动发一帧），`uart.v` 是通用版，留给以后用。

---

### 26. `rtl/display_seg.sv` —— 数码管动态扫描（74 行）

**作用**：8 位数码管，用"位选 + 段选"的时分复用方式点亮。

**原理**：每次只点亮一位，但切换得足够快（>50 Hz），人眼看到的就是 8 位同时亮。

```systemverilog
// 16 分频后，高/低半周期各点亮 4 位
assign ans = count[4] ? 8'b1010_1010 : 8'b0101_0101;
```

---

### 27. `rtl/seg7.sv` —— 七段译码（56 行）

**作用**：把 4 位十六进制数变成 7 段码。

```systemverilog
case (din)
    4'h0: dout = 7'b011_1111;   // a b c d e f 亮
    4'h1: dout = 7'b000_0110;   // b c 亮
    ...
    4'hF: dout = 7'b111_0001;
endcase
```

位序：`dout[6]=g, [5]=f, [4]=e, [3]=d, [2]=c, [1]=b, [0]=a`。

## 七、文件之间的依赖关系

```
cpu_para.sv  （宏，被所有文件 include/重复定义）
    │
    ├── cpu_Reg.sv ──────────────┐
    ├── cpu_add.sv ──► cpu_ALU.sv ──► cpu_EXU.sv
    ├── cpu_sext.sv ─► cpu_LSU.sv
    │
    ├── cpu_RegisterFile.sv ─┐
    ├── cpu_CSR.sv ──────────┴──► cpu_Reg_Stack.sv ──► cpu_IDU.sv
    │
    ├── cpu_IFU.sv ──┐
    ├── cpu_IDU.sv ──┴──► cpu_IFID_EX_Reg.sv ──► cpu_EXU.sv
    │                                              │
    ├── cpu_EX_LSWB_Reg.sv ◄───────────────────────┘
    │        │
    │        └──► cpu_LSU.sv ──► cpu_WBU.sv
    │
    ├── cpu_Data_hazard.sv ──► cpu_Control.sv
    │
    └── 以上全部 ──► cpu_myCPU.sv ──► top.v
                                        │
                                        ├── IROM.v
                                        ├── DRAM.v ◄── dram_driver.sv
                                        ├── perip_bridge.sv
                                        └── counter.sv
```

**改代码时的原则**：

- 只改 `cpu_myCPU.sv` 的连线 → 不会影响任何模块内部
- 改 `cpu_Control.sv` → 会同时影响旁路、停顿、冲刷，一定要重跑仿真
- 改 `cpu_IDU.sv` 的立即数 → 一定会影响 `lui/jal/branch`，跑测试程序验证
